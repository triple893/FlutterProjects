# DECISION_LOG.md - FlutterProject 意思決定ログ

## 2025年8月8日

- **決定事項:**
    - **クロスプラットフォーム開発フレームワークとして、Flutterを採用することを決定。**
    - **開発環境として、ローカルPCへのインストールを必要としないクラウドベースのGitHub Codespacesを利用することを決定。**

- **背景:**
    - 複数のOS（Android, iOS）に対応するアプリを、効率的に開発する必要があった。
    - 開発者（丼ちゃん）のPCに、複雑な開発環境をインストールする負担をなくし、AIエージェント（あるま）が環境構築を自動化できる方法を模索していた。

- **理由:**
    - **Flutter:** Googleが主導で開発しており、高いパフォーマンスと美しいUIの実現に定評がある。単一のコードベースで複数のプラットフォームに対応できるため、開発効率が飛躍的に向上する。
    - **GitHub Codespaces:** `.devcontainer.json` という設定ファイルを用いることで、開発環境の構築をコード化し、完全に自動化できる。これにより、AIエージェントによるセットアップが可能となり、開発者は本来のアプリケーション開発に集中できる。

- **検証:**
    - AIエージェント（あるま）による事前調査の結果、GitHub Codespaces上で、コマンドライン操作を主体としたFlutter開発環境の自動構築が可能であると判断した。

## 2026年10月19日

- **決定事項:**
    - **DonzLab ポータルを EmDash で作り、それを EmDash 導入の PoC（お試し版）とする。**
    - **PoC の間は非公開とし、AI は下書きまで・公開は丼ちゃんが行う運用を前提にする。**

- **背景:**
    - EmDash は AI が MCP 経由でコンテンツを作成・更新できる CMS で、AI 化が進んだ DonzLab の環境と相性が良い。
    - 一方、反証レビュー（`docs/EMDASH_COUNTER_REVIEW.md`）で、安定版の実績の浅さ・AI の書き込み権限のリスク・日本語検索の弱さを指摘した。

- **理由:**
    - 新規の小規模サイトなので、うまくいかなくても失うものが小さい。
    - 前から作りたかった DonzLab ポータルを題材にすれば、PoC の成果がそのまま本番の最初の版になる。

- **検証:**
    - `docs/EMDASH_POC_RESULT.md` を参照。MCP での下書き作成・差分確認・競合防止・権限外操作の拒否を確認した。日本語検索は trigram で改善したが、2文字の語はヒットしない。

## 2026年10月20日

- **決定事項:**
    - **`donzlab-portal/` は本番実装の前のモック（見本）とする。** Don'z Lab.com を「城」とし、ラボのカードから各ラボの世界に入る構成にする。没入感と美しいグラフィックを最優先し、ビジネス系のページだけはクリーンな構造にする。
    - **Re:IDOL ファンポータルを載せる。** ファンポータルには専用のトップページがあるため、城にはリンクと解説のカードだけを置く。
    - **音色ちゃんは、アイドルとしての情報だけを使う。** 家族としての個人の情報は載せない。
    - **アイドルとしての情報は、運営（三宅さん）の許可を得てから公開する。** それまでは「準備中」とし、リンクは空にしておく。
    - **ProjectNeiro（法務関連）は載せない。**

- **理由:**
    - このサービスを使う意味の一つは、日本の技術を世界に見せることにある。
    - 公開の範囲は、関わる人の立場ごとに分ける。
