## 0. 目的（一行）

**丼ちゃんの意図を、クロCEOが「安全かつ一回で」判断できる〈材料・選択肢・推奨案・指示案〉へ変換する、非権威的な補佐機能を設置する。**

- 支援室は **何も発行せず・何も承認せず・何も実行しない**。準備（材料化）だけを行う。
- 権威はすべて既存の指揮系統（DISPATCH_LEDGER＝実行、丼ちゃん判子＝憲法級、クロCEO＝裁定）に残す。支援室はその手前で「判断の一発化」を助けるスタッフ機能。
- 本DIRECTION案の狙いは、この機能の①配置②構成③スキーマ④ゲート⑤接続⑥パイロット⑦承認事項を一括で決める材料を、丼ちゃん自身が一回で判子できる形にまとめること。

## 2. フォルダ構成

```
_project_control/_soudan/
  README.md                       # 起動読込セット除外の明記・authority:none・運用規律・機械ゲート起動法
  SOUDAN_TEMPLATE.md              # 相談MDの雛形（authority:none / read_policy:never_first を先頭コメントで固定明記）
  detect_soudan_gate.py           # 完全性＋権限ゲートの機械検出器（本設置後の常駐置き場。パイロット中はscratch）
  SOUDAN_<YYYYMMDD>_<slug>.md     # 個別相談（状態はfrontmatter status で管理）
  _archive/                       # promoted / dropped を退避し、活性リストを短く保つ
```

- **命名規則**: `SOUDAN_YYYYMMDD_<topic-slug>.md`（例: `SOUDAN_20260723_themis_model_check.md`）。
- **状態はサブフォルダでなくfrontmatter `status`** で持つ（open/parked/promoted/dropped）。物理移動は promoted/dropped 化した時に `_archive/` へ退避するのみ。
- **ゲート検出器の所在**: パイロット中はscratch上（§6）。本設置時に `_soudan/detect_soudan_gate.py` として常駐（この置き場自体は非権威ツール＝read_first対象外）。
- **孤児化防止（L-033/L-036の教訓）**: 相談が参照する材料は相談MD内に **引用または相対リンク**で内包し、実体を別所に散らさない。移送が必要な材料が出たら、それはLedger案件（コデ移送）として別途起票する。

## 3. 相談MD（SOUDAN）のスキーマ

### frontmatter

```yaml

authority: none            # 【この行のみ不変・書換禁止】実行/承認の根拠に引用不可
read_policy: never_first   # 【v2】起動読込セットに含めない（非権威・材料）
soudan_id: S-YYYYMMDD-nn   # 相談専用ID空間。L-NNN空間と衝突させない（L-033 F2の教訓）
title:
requested_by:              # 発案者（丼ちゃん / kuro / codex / gura）
prepared_by:               # 起草者（kuro / codex / gura）
committed_by: codex        # 【v2】_soudanへ確定書込した単一Writer（§4）
for_decider: kuro | 丼ちゃん # この材料が誰の「一回判断」を支援するか（§4宛先ゲート）
effective_from: null       # 常にnull（非権威ゆえ発効しない）
status: open | parked | promoted | dropped   # ←遷移して良い（不変対象ではない）
review_by:                 # クロ査読期限（§5の軽量滞留規律）
expires_when:              # 失効条件（例: L-038段階1完了時）
promotes_to:               # 昇格先の権威文書種別 + 発行後ID（DIRECTION/DECISION/STANDARD/MISSION + L-NNN）

created_at:

```

> **不変の範囲（v2明確化）**: 「書換禁止」は `authority: none` の**行のみ**。`status`・`updated_at`・`promotes_to` 等は運用上遷移する。ファイル全体を凍結する意味ではない。

### 本文8節（＝意思決定支援パッケージの核心）

判断者が **一回で・安全に** Yesと言えるだけの材料を、この順で必ず載せる。

1. **論点** — 決めるべき事を一文で。「何を判断するのか」。
2. **丼ちゃんの意図（一次記録）** — 丼ちゃんの生の発話を逐語／準逐語で固着（引用・リンク）。※穴10（発話を一次記録に残す仕組みが無い）の是正。
3. **材料（事実）** — 証拠を出典付きで。read-onlyの事実のみ。事実を超えた断定はしない。
4. **選択肢** — 相互に排他な2〜4案（yes/noの二択も可）。各案にコスト／リスク／可逆性、および **触れる正典** を明記。
5. **推奨案** — 1案を推奨＋理由。**「助言であり決定ではない」と明示**。
6. **指示案** — 判断者が一発で発行できる権威文書の下書き（例: DIRECTION/MISSION草案）。**「案・未発効」と明示**。
7. **一回判断チェックリスト** — 判断者が安全にYesと言うために確認すべき項目: 完全性・権限・可逆性・境界（触れる／触れない）・外部送信有無。
8. **危険・未確定** — 未解決点を正直に列挙。断定しない（切り分け表へ写像）。

## 4. 宛先・完全性・権限ゲート

3つのゲートを機械検出可能な規律として置く（D2で実装済みの「発火する検出器」パターンを流用・拡張）。

- **宛先ゲート**: 全相談は `for_decider`（kuro か 丼ちゃん）を明示する。妥当な判断者が無い相談は不完全＝提示不可。
- **完全性ゲート**: 相談が「decision-ready」になるのは、本文1〜7節が全て存在し非空、選択肢≥2（yes/no可）、推奨案あり、指示案あり、一回判断チェックリスト充填済みのとき **のみ**。機械チェックが節の存在を検証してからクロ査読へ。未達→statusはopenのまま、判断に提示できない。
- **【v2】Writer規律**: 相談の起草（材料集め・草案）は kuro/codex/gura の誰でもスクラッチ上で行ってよい。ただし **`_soudan/` への確定書込は コデ（単一Writer）に一本化** する（`committed_by: codex`）。非権威レーンでも multi-writer 競合（L-030系の混乱）を持ち込まない。
- **権限ゲート**:
  - `authority: none` は不変（書換禁止・§3の範囲）。
  - **SOUDAN MDは、いかなる実行・承認の根拠としても引用不可。**
  - **【v2】検出はフィールド文脈で判定する**（単なるsoudan_id出現のgrepではない）:
    - `soudan_id` が他文書に現れてよいのは **`related:`（来歴）フィールドのみ**。
    - MISSION/DIRECTION/DECISION/LEDGER の `authority:` / 根拠 フィールド・根拠節に `soudan_id` が現れたら **違反として発火**。
    - すなわち「provenance参照（可）」と「根拠引用（不可）」を、出現フィールドで機械分離する。
  - open→（推奨）→提示 はクロのみ。権威化（promote）は丼ちゃん判子（またはクロの3類型自裁, L-031）でのみ。権威文書とLedgerの物理書込はコデ（単一Writer）のみ。
  - 支援室そのものは発行も実行もしない。

## 5. Ledger／NOW／憲法との接続方法

- **DISPATCH_LEDGER**:
  - 支援室に新L発番なし。相談が昇格した時、**結果の権威文書**が通常のLedger処理（新L or 既存L更新, コデ書込）を受ける。相談の `promotes_to` に結果のL-NNNを記録。
  - 設置事実はL-025備考へ1行: 「HQ配下・非権威の相談サブレーン `_soudan\` を設置」。
  - **【v2】滞留サーフェスはLedger掃引に一本化**: 相談ファイルはLedger本体の滞留メトリクス（48hルール）は汚さないが、クロの毎セッション掃引の中で **「`_soudan` の review_by 超過件数」を1行カウンタとして必ず出す**。「クロが覚えてる」頼み（＝台帳が潰した穴の再来）を廃止し、既存の掃引規律に乗せて相談が静かに腐るのを防ぐ。
- **NOW.md**:
  - 支援室は読み文脈であって実行WIPではない。**WIP上限2件（L-023）には計上しない**（準備であって実行でないため）。
  - **【v2】WIPバイパス防止ガード**: 相談MDは「準備・材料化」に限る。実行（ファイル改変・移送・正典変更・外部送信）を相談レーンで走らせてWIP上限を回避してはならない。作業が実行の性質を帯びた瞬間、それはLedger案件として起票し、WIPスロットを1つ消費する。
  - NOW.mdへ1行ポインタ: 「非権威の意思決定支援室 `_soudan/` 稼働中（材料化のみ・実行はLedger経由）」。
- **憲法／正典群**:
  - 支援室の出力は、各選択肢が触れる正典を明記（追跡可能性）。指示案は既存正典（COMMAND_OS_INDEX階層・DIRECTIVE補則2 tier規律・STANDARD routing 等）と整合していること。
  - 支援室は **正典を改変できない**。正典改訂は指示案として「案」を書けるだけで、発効は通常の判子ルート。`authority:none`＋`read_policy:never_first` がこれを構造的に担保する（`_soudan` 内は決して read_first 正典にならない）。

## 6. scratchで行う最小パイロット

- **対象（実在・低リスクの1件）**: 「L-038 Themis 段階1へ〈model明示チェック〉を追加するか否か」。DIRECTION 20260723a が明示的に別判子へ繰延べた実在の決定事項＝支援室の初仕事に最適。
  - ※本設置未承認の段階では、このパイロット相談は**成果物として使い回さない**（機構承認後に正式相談として作り直す）。パイロットはあくまで機構の発火実証。
- **手順**: この1件について本文1〜8節を満たす **相談MDを1本 scratch上に作成** → 完全性＋権限の機械ゲートを通す → クロが一回査読し、パッケージが本当に「一発・安全な判断」を可能にしたかを判定。
- **成功基準（物理観測・自己申告不可）**:
  1. 完成パッケージで完全性ゲートがPASS、かつ **わざと1節欠いた複製で FAIL** すること（発火の物理観測。D2と同じ規律）。
  2. **【v2】** `soudan_id` を `related:` に置いた文書は通し、`authority:`/根拠 フィールドに置いた複製で権限ゲートが **検出発火** すること（フィールド文脈判定の実証）。
  3. クロが「追加質問ラウンド無しで一回判断できたか（Yes/No、Noなら欠けていた節）」を記録。
- **実装**: D2の `detect_tier_violations.py` の exit-code/ゲート様式を流用し、SOUDAN節完全性＋根拠引用（フィールド文脈）チェックを追加した薄い検出器 `detect_soudan_gate.py` をscratchに置く。
- **報告**: 事実ベース・原因は断定せず切り分け表へ。正常系だけで完了扱いにしない。
